# Hubから利用状況を同期する

## 主アクター
利用者（アプリケーションを起動・終了する）

## 目的
設定した各Hubの最新利用状況をローカルのSQLiteに保存し、閲覧時にHubへ接続しなくても最新状態を利用できるようにする。

## 前提
1件以上のHubについて、ID・表示名・URL・認証トークンを記載した接続設定ファイルがGit管理外に用意され、`.env` の `HUB_CONFIG_PATH` がそのファイルを指している。

## 共通の受け入れ条件
- URLと認証トークンをDB、ログ、閲覧側へ渡すデータに含めない。アプリケーションは設定ファイルを更新しない。
- Hubごとに最新状態と受信時刻だけを保持し、受信履歴は保存しない。同じ情報を再受信しても利用量を二重に加算しない。
- あるHubの失敗は、他のHubの受信とWebサーバーに波及しない。

## 未着手のシナリオ
主成功シナリオの完了後に1本ずつ全文を検討する候補。名称と分岐条件だけを置く。

- Hubの認証に失敗する: Hubへの接続で認証を拒否された
- Hubが不正なHTTP応答を返す: リダイレクトを含め、SSEとして受け付けられない応答が返った
- Hubが不正な通知を送る: 形式・必須項目の不正、解釈できないバイト列、最初の全体状態より前の差分通知を受けた
- 受信データの保存に失敗する: 保存のトランザクションが失敗した
- Hubとの通信が切れる: 接続に失敗した、または受信中にストリームが終了した
- 接続設定が不正なため起動しない: ファイルがない、JSONが不正、必須項目の欠落、URLの形式不正、Hubが0件、IDの重複
- 保存済みの状態があるまま再起動する: 以前の受信で保存した状態がある
- 表示名やURLを変えて再起動する: 同じIDで表示名やURLを変えた設定で起動した
- 設定から外したHubを残したまま起動する: 以前登録したHubが設定から消えている
