# 設定したHubの最新状態を受信して保存する

- 種別: 主成功
- UI確認: 不要

## 開始条件
利用者がアプリケーションを起動する。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者がアプリケーションを起動する | DBに登録済みのHubのうち、URLと認証トークンがどちらも空でないものを読み、受信状態を「受信中」にする。URLまたは認証トークンが空のHub（移行前から登録されていたHub）は受信せず、受信状態は「再接続中」のままにする。Hubごとに独立したSSE接続を開始する。登録済みのHubが0件なら、接続せずにWebサーバーだけを起動する |
| 2 | Hubが接続時の全体状態（snapshot）を送る | 形式と必須項目を検証し、受信元のHubに紐づけて最新状態と受信時刻を一括で保存する。日別の履歴を含むときは、そのHubの日別の集計行を、受け取った日付ごとに上書きまたは追加する。受け取っていない日付の保存済みの行は変えない。報告された利用枠を追加または更新し、報告されなくなった枠を下の規則で保持または削除する。保存の確定後、閲覧側へ変更を通知する |
| 3 | Hubが全体更新（stats）を送る | 検証し、当該Hubの最新状態を全体置換して受信時刻とともに保存する。手順2と同じく日別の集計行を日付ごとに上書きまたは追加し、日別の履歴を含まないときは保存済みの日別の集計行を変えない。報告された利用枠を追加または更新し、報告されなくなった枠を下の規則で保持または削除する。保存の確定後、閲覧側へ変更を通知する |
| 4 | Hubが鮮度更新（freshness）を送る | 検証し、保存済みの状態を読まずに、当該Hubの受信時刻とHubの更新時刻、通知に含まれる端末ごとの更新時刻と古さだけを更新する。利用量・利用枠・stats全体の受信データは変えない。保存の確定後、閲覧側へ時刻の更新を通知し、Hub IDと更新した時刻・古さを渡す |
| 5 | 利用者がアプリケーションを終了する | 全Hubの受信を止め、処理中の保存が確定してからDBを閉じる |

利用枠の保存:
- 報告された利用枠は、残量、次のリセット時刻、枠の長さなどを最新の受信値で更新する。
- 利用枠が報告されなくなっても、最後に記録した次のリセット時刻を過ぎるまで、最後の値のまま保持する。保持している枠は、報告された枠と同じように利用枠の一覧へ含め、報告が途切れていることを示す区別は設けない。
- 報告されていない枠は、そのHubの次のsnapshot・statsの保存で、受信時刻が最後に記録した次のリセット時刻を過ぎていれば削除する。次のリセット時刻を持たない枠は、報告されなくなった時点で削除する。Hubを削除したときは、そのHubの利用枠もすべて削除する。

## 受け入れ条件
- 登録した全Hubから独立して受信し、初回と更新後の最新状態を、保存処理とは別のDB接続からHubごとに読み取れる。
- 状態を未受信のHubも、IDと表示名で識別できる。
- URLまたは認証トークンが空のHubには接続せず、保存済みの状態を保持する。他のHubの受信は妨げない。
- snapshot・statsの保存が確定するたびに、閲覧側の通知の受け口で変更の合図を受け取れる。合図には利用データ・URL・認証トークンを含まない。
- freshnessでは、受信時刻・Hubの更新時刻・端末の更新時刻と古さだけが変わり、利用量・利用枠は変わらないことを、保存処理とは別のDB接続から読み取れる。保存の確定後、閲覧側の通知の受け口で、変更の合図とは別の種別で時刻の更新を受け取れる。これにはHub ID・受信時刻・Hubの更新時刻・端末ごとのIDと更新時刻と古さだけを含み、利用量・URL・認証トークンを含まない。
- freshnessの保存では、保存済みの状態をDBから読まない。
- heartbeatでは保存も通知もしない。
- 利用枠がsnapshot・statsに含まれない受信を挟んでも、その枠の次のリセット時刻より前なら行が削除されず、最後に記録した残量・次のリセット時刻・枠の長さを保持することを、保存処理とは別のDB接続から読み取れる。その枠は閲覧側の利用枠の一覧にも含まれる。
- 次の受信で枠が再び報告された場合は、残量・次のリセット時刻・枠の長さが最新の受信値になる。
- 報告されなくなった枠は、受信時刻が最後に記録した次のリセット時刻を過ぎた後の、そのHubの最初のsnapshot・statsの保存で削除される。次のリセット時刻を持たない枠は、その枠が報告されなくなった受信の保存で削除される。
- Hubを削除すると、そのHubの利用枠も残らない。
- 日別の集計行（日付、トークン数、推定コスト）は、受信のたびに、受け取った日付だけを上書きまたは追加する。同じ状態を2回受信しても、保存済みのトークン数が変わらないことを、保存処理とは別のDB接続から読み取れる。
- 受信した履歴に含まれない古い日付の保存済みの行が、受信後も消えず、値も変わらない。
- 日別の履歴を含まない受信では、保存済みの日別の集計行が消えない。
- 起動時と snapshot・stats・freshness の保存時に、上限金額の推定用データ、月換算上限額・支払額の日次記録、プランの価格表を作成・更新しない。
- アプリケーションの更新時に、上限金額専用のテーブルと列を削除する。Hubの登録情報、利用実績、端末別の日次モデル明細、契約、利用枠の残量・リセット時刻・長さ・メーター変更時刻は保持する。新規DBと更新後のDBに `daily_monthly_limits`・`plan_prices`・`limit_window_baseline_costs` は存在せず、再起動と受信後も再作成されない。
