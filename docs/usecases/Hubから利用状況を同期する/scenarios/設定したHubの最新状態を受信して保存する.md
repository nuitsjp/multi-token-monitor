# 設定したHubの最新状態を受信して保存する

- 種別: 主成功
- UI確認: 不要

## 開始条件
利用者がアプリケーションを起動する。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者がアプリケーションを起動する | 接続設定ファイルを読み、必須項目・ID重複・URL形式を検証する。各HubのIDと表示名をDBへ登録し、Hubごとに独立したSSE接続を開始する |
| 2 | Hubが接続時の全体状態（snapshot）を送る | 形式と必須項目を検証し、受信元のHubに紐づけて最新状態と受信時刻を一括で保存する。保存の確定後、閲覧側へ変更を通知する |
| 3 | Hubが全体更新（stats）を送る | 検証し、当該Hubの最新状態を全体置換して受信時刻とともに保存する。保存の確定後、閲覧側へ変更を通知する |
| 4 | Hubが鮮度更新（freshness）を送る | 既存状態の時刻・鮮度情報だけを更新して保存し、利用量・上限などは維持する。保存の確定後、閲覧側へ変更を通知する |
| 5 | 利用者がアプリケーションを終了する | 全Hubの受信を止め、処理中の保存が確定してからDBを閉じる |

## 受け入れ条件
- 設定した全Hubから独立して受信し、初回と更新後の最新状態を、保存処理とは別のDB接続からHubごとに読み取れる。
- 状態を未受信のHubも、IDと表示名で識別できる。
- 保存が確定するたびに、閲覧側の通知の受け口で変更の合図を受け取れる。合図には利用データ・URL・認証トークンを含まない。
- heartbeatでは保存も通知もしない。
