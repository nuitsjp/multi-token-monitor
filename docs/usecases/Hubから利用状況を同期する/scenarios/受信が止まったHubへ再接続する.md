# 受信が止まったHubへ再接続する

- 種別: 拡張
- UI確認: 不要

## 分岐条件
主成功シナリオで、あるHubへの接続の開始時または受信中に、次のいずれかの理由でそのHubからの受信を続けられなくなった。

- 接続に失敗した、または受信中にストリームが終了した
- 認証を拒否された
- リダイレクトを含め、SSEとして受け付けられない応答が返った
- 形式・必須項目の不正、解釈できないバイト列、または最初の全体状態より前の差分通知を受けた
- 受信データを保存するトランザクションが失敗した

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | Hubからの受信が続けられなくなる | 当該Hubの接続を閉じる。保存中の変更はロールバックし、最後に保存できた状態を維持する。当該Hubの受信状態を「再接続中」として記録し、閲覧側へ変更を通知する。Hub IDと原因の分類をログに出力する |
| 2 | 再接続までの待ち時間が経過する | 当該Hubへ新しいSSE接続を開始する |
| 3 | 再接続した接続で、全体状態（snapshot）を保存する前に受信が続けられなくなる | 接続を閉じ、Hub IDと原因の分類をログに出力する。待ち時間を前回の2倍（上限60秒）にして手順2へ戻る。受信状態は「再接続中」のままとし、通知はしない |
| 4 | Hubが再接続した接続で全体状態（snapshot）を送る | 主成功シナリオと同じく検証して保存する。当該Hubの受信状態を「受信中」として記録し、閲覧側へ変更を通知する。次に受信が止まったときの待ち時間を初期値の1秒に戻す。以後は主成功シナリオの stats・freshness の受信に戻る |
| 5 | 待ち時間の経過を待っている間に、利用者がアプリケーションを終了する | 待ち時間の経過を待たずに受信を止め、主成功シナリオと同じく終了する |

## 受け入れ条件
- 分岐条件のどの理由で受信が止まっても、回数の上限なく再接続を試みる。
- 再接続までの待ち時間は、受信が止まった直後が1秒で、連続して失敗するたびに2倍になり、60秒を超えない（1、2、4、8、16、32、60、60…秒）。
- 再接続した接続で全体状態を保存できたら、次に受信が止まったときの待ち時間は1秒に戻る。
- 再接続中も、他のHubの受信とWebサーバーは続き、当該Hubの最後に保存した状態は保存処理とは別のDB接続から読み取れる。
- 受信状態が「受信中」と「再接続中」の間で変わるたびに、その受信状態を保存処理とは別のDB接続から読み取れ、閲覧側の通知の受け口で変更の合図を受け取れる。再接続の失敗が続いて受信状態が変わらない間は合図しない。
- 待ち時間の経過を待っている間に終了しても、待たずに終了する。
- ログにはHub IDと原因の分類だけを出力し、URL・認証トークン・Hubの応答本文を含めない。
