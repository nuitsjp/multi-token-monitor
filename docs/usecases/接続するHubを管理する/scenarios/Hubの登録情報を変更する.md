# Hubの登録情報を変更する

- 種別: 拡張
- UI確認: 要

## 分岐条件
[Hubを追加する](Hubを追加する.md) の手順1で `/settings` を表示した後、利用者が追加ではなく、登録済みのHubの表示名・URL・認証トークンを変更する。登録済みのHubが1件以上ある。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者が一覧のHubの行にある変更のアイコンボタン（鉛筆、名称「Edit hub」）を押す | 画面の中央に重ねて、見出し「Edit hub」のポップアップを開く。Name と URL には現在の登録値を入れ、Token は空にする。認証トークンの現在値は表示しない |
| 2 | 利用者が変えたい項目を入力し直して Save hub を押す。Token を空のままにすると、登録済みの認証トークンを変更しない | 入力を [共通の受け入れ条件](../README.md#共通の受け入れ条件) の検証にかける。すべて満たし、かつ URL または Token が変わる場合は、変更後の接続先へ、変更後の認証トークン（Token が空なら登録済みの値）で接続を試す。接続の応答を受ければ、対象のHubのIDを変えずに変更した項目をDBへ保存し、保存の確定後に閲覧側へ変更を通知する。ポップアップを閉じ、一覧の同じ位置に変更後の表示名・URLを示す。表示名だけが変わる場合は接続を試さず保存する |
| 3 | （システムが続ける）変更したHubが新しい接続先から接続時の全体状態（snapshot）を送る | 変更前の接続を終了し、アプリケーションの再起動なしに、変更後のURLと認証トークンで受信を開始する。[Hubから利用状況を同期する](../../Hubから利用状況を同期する/README.md) の主成功シナリオに従って保存し、最初の全体状態で保存済みの最新状態を置き換える。一覧の受信状態は Connected になる |

画面の規則:
- 変更のアイコンボタンは、一覧の各行の右端に置く。ポップアップの大きさ・配置・閉じ方・検証のしかたは、追加のポップアップと同じにする。
- ポップアップを開くたびに、そのHubの現在の登録値から始める。×ボタンまたは外側の操作で、保存せずに閉じる。
- 接続の確認は [共通の受け入れ条件](../README.md#共通の受け入れ条件) に従う。失敗したときは、ポップアップを開いたまま、保存せず、入力値を残し、Token の項目のそばにメッセージを示す。

## 受け入れ条件
- 一覧の各行に変更のアイコンボタンがあり、押すと Name・URL に現在の登録値が入り、Token が空のポップアップが開く。閉じて開き直すと、保存していない入力は残らず現在の登録値に戻る。
- Token を空のまま Save hub を押すと、Token は変更されない。表示名・URLを変えた場合は、変更した項目だけがDBで更新され、同じIDのHubの認証トークンは変わらない。
- URL または Token を変えて Save hub を押すと、変更後の接続先へ接続を試し、応答を受けた場合に限りDBが更新され、ポップアップが閉じ、一覧の同じ位置に変更後の表示名・URLが示される。Hubの数と並び順は変わらない。
- 接続の確認が失敗すると、共通の受け入れ条件のメッセージが Token の項目のそばに表示され、ポップアップは開いたまま、DBの値も受信も変わらず、入力値が残る。
- 表示名だけを変えた場合は、接続を試さずに保存する。
- 検証に該当する入力では、対応するメッセージがポップアップ内の項目のそばに表示され、接続を試さず、ポップアップは開いたまま、DBの値も受信も変わらず、入力値が残る。登録済みの認証トークンが空のHubで Token を空にした場合も該当する。
- 変更したHubは、アプリケーションを再起動せずに、変更前のURLへの接続を終了し、変更後のURLへ変更後の認証トークンで受信を開始する。変更前の認証トークンでの再接続は行われない。
- 変更したHubの最初の全体状態を受けるまで、保存済みの最新状態と日次明細は変わらず、受けた後に最新状態が置き換わり、他のページを開き直さずに反映される。日次明細は削除されない。
- 追加のとき URL と認証トークンが空だったHubも、URLと Token を入れて保存すると、接続の試行に応答を受けた場合に限り保存され、受信を開始する。
- 変更したHubの接続の失敗は、他のHubの受信とWebサーバーを止めない。
- 認証トークンは、DBの値を除き、画面・閲覧用API・ログ・通知に現れない。URLは設定画面にだけ表示される。
