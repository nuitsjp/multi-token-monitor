# Hubの登録情報を変更する

- 種別: 拡張
- UI確認: 要

## 分岐条件
[Hubを追加する](Hubを追加する.md) の手順1で `/settings` を表示した後、利用者が追加ではなく、登録済みのHubの表示名・URL・認証トークンを変更する。登録済みのHubが1件以上ある。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者が一覧のHubの行にある変更のアイコンボタン（鉛筆、名称「Edit hub」）を押す | 画面の中央に重ねて、見出し「Edit hub」のポップアップを開く。Name と URL には現在の登録値を入れ、Token は空にする。認証トークンの現在値は表示しない |
| 2 | 利用者が Name・URL・Token を入力し直して Save hub を押す | 入力を [共通の受け入れ条件](../README.md#共通の受け入れ条件) の検証にかける。すべて満たせば、対象のHubのIDを変えずに表示名・URL・認証トークンをDBへ保存し、保存の確定後に閲覧側へ変更を通知する。ポップアップを閉じ、一覧の同じ位置に変更後の表示名・URLを示す |
| 3 | （システムが続ける）変更したHubが新しい接続先から接続時の全体状態（snapshot）を送る | 変更前の接続を終了し、アプリケーションの再起動なしに、変更後のURLと認証トークンで受信を開始する。[Hubから利用状況を同期する](../../Hubから利用状況を同期する/README.md) の主成功シナリオに従って保存し、最初の全体状態で保存済みの最新状態を置き換える。一覧の受信状態は Connected になる |

画面の規則:
- 変更のアイコンボタンは、一覧の各行の右端に置く。ポップアップの大きさ・配置・閉じ方・検証のしかたは、追加のポップアップと同じにする。
- ポップアップを開くたびに、そのHubの現在の登録値から始める。×ボタンまたは外側の操作で、保存せずに閉じる。
- Token は変更のたびに入力する。空のまま Save hub を押すと、共通の検証のメッセージを示して保存しない。
- 保存の前に接続の確認は行わない。接続できない場合は一覧の受信状態が Reconnecting になる。

## 受け入れ条件
- 一覧の各行に変更のアイコンボタンがあり、押すと Name・URL に現在の登録値が入り、Token が空のポップアップが開く。閉じて開き直すと、保存していない入力は残らず現在の登録値に戻る。
- 検証を満たす入力で Save hub を押すと、同じIDのHubの表示名・URL・認証トークンがDBで更新され、ポップアップが閉じ、一覧の同じ位置に変更後の表示名・URLが示される。Hubの数と並び順は変わらない。
- 検証に該当する入力では、対応するメッセージがポップアップ内の項目のそばに表示され、ポップアップは開いたまま、DBの値も受信も変わらず、入力値が残る。Token を空にした場合も該当する。
- 変更したHubは、アプリケーションを再起動せずに、変更前のURLへの接続を終了し、変更後のURLへ変更後の認証トークンで受信を開始する。変更前の認証トークンでの再接続は行われない。
- 変更したHubの最初の全体状態を受けるまで、保存済みの最新状態と日次明細は変わらず、受けた後に最新状態が置き換わり、他のページを開き直さずに反映される。日次明細は削除されない。
- 表示名だけを変更し、URLと認証トークンを同じ値で入れ直した場合も、同じ手順で保存され、受信は変更後の登録値で続く。
- 追加のとき URL と認証トークンが空だったHubも、この手順で接続情報を入れると受信を開始する。
- 変更したHubの接続の失敗は、他のHubの受信とWebサーバーを止めない。
- 認証トークンは、DBの値を除き、画面・閲覧用API・ログ・通知に現れない。URLは設定画面にだけ表示される。
