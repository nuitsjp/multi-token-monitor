# 保存済みの最新利用状況を1画面で見る

- 種別: 主成功
- UI確認: 要

## 開始条件
利用者がブラウザーでアプリケーションの画面（`/`）を開く。

## 手順
| # | アクター | システム |
| --- | --- | --- |
| 1 | 利用者が画面を開く | 保存済みのドメインモデルを読み、次の5区画を1画面に表示する。期間は「今日」を選択した状態で表示する。左上に全体の合計、その下に Hub別、右にツール・モデル別の内訳を置く。利用枠と端末はその下に置く |
| 2 | 利用者が期間（今日・今月・累計）を切り替える | 全体の合計、Hub別、ツール・モデル別の内訳の区画を、選択した期間の値に切り替える。利用枠と端末の区画は変えない |
| 3 | Hubが3件以上あるとき、利用者が Hub別のページを送る | そのページのHubを2件表示する。他の区画と期間の選択は変えない |
| 4 | 利用者が利用枠の区画でHubを切り替える | 選択したHubが報告した利用枠を表示する。他の区画と期間の選択は変えない |
| 5 | 利用者が画面を再読み込みする | その時点の保存済み状態で表示し直す。Hub別のページは先頭に戻る |

表示する区画:
1. 全体の合計: 全Hubのトークン数と推定コスト（USD）の合計。
2. Hub別: Hubごとに表示名、最終受信時刻、Hubの更新時刻、トークン数、推定コスト。状態を未受信のHubは表示名と「未受信」を示す。1ページに2件、区画の高さは2件分とする。3件目以降はページを送って表示する。最後のページが1件のときも、空の2件目で高さを保つ。Hubが1件のときはページ送りを出さない。
3. ツール・モデル別の内訳: 全Hubを合算したツール×モデルごとのトークン数と推定コスト。トークン数の多い順に上位5件を個別に示し、6位以降は「Other」1件に合算してモデル数を添える。
4. 利用枠: 期間と同じ形式の切り替えでHubを選び（初期表示は一覧の先頭のHub）、そのHubが報告した利用枠を、契約（提供元＋アカウント）ごとに円のメーターで示す。切り替えの左に凡例を置く。表示対象の枠の選び方は現行のまま変えない。
5. 端末: Hub、ホスト名、OS名、最終送信時刻と、鮮度切れの端末の目印。

利用枠の円:
- 円は、契約×枠グループごとに1つ作る。枠グループは、枠のラベルから末尾の枠名（`5-hour`・`5h`・`session`・`weekly`・`daily`・`monthly`、大文字小文字を区別しない）を除いた部分とする。除いて空になる場合は、契約全体で1グループとする。
- 1つの円には枠を最大2つ重ね、長さの短い順に外側から並べる。長さが不明な枠は最後に置く。1つのグループに枠が3つ以上あるときは、長さ順に2つずつ円に詰め、余りは同じグループの次の円にする。枠が1つの円は、外側の位置に1本だけ描く。
- 円弧は下部を開けた270度で、端は丸める。円弧の長さは残量（%）に比例する。
- 円の中は、上から、提供元のアイコン、名前の行、各枠の「残量% 枠ラベル」を1行ずつ置く。名前の行は、グループが1つの契約では「提供元 · プラン」、グループが複数の契約では「提供元 · グループ名」とする。グループが複数の契約は、その契約の円の列の上に、見出しとして「提供元 · プラン」を1行置く。
- 円の下に、枠ごとに1行を置く。左から、枠ラベル、時計アイコン、残り時間、「≈」、推定上限額の順とする。列の幅は、円ごとに、その円の行の中で最も広い内容に合わせ（余白は一定の小さな間隔だけ）、同じ円の行どうしで列の位置を揃える。枠ラベルと時計アイコンと「≈」は中央、残り時間は左寄せ、金額は右寄せとする。推定上限額を求められない枠は、「≈」の列を空けたまま、金額の列に「Estimating」を右寄せで置く。画面に「Limit」の語は使わない。

月換算上限額: 円の右上に、その円で推定上限額が求められている枠のうち最も長い枠の推定上限額を31日（44,640分）に換算した金額を、`$643/mo` の形（整数のドル）で示す。換算は「推定上限額 ÷ 枠の長さ（分） × 44,640」とする。約1か月（28〜31日）の枠は、換算せず推定上限額をそのまま示す。推定上限額が求められている枠がない円、または枠の長さが不明な円は、何も示さない。金額が4桁以上でも円に重ならないよう、円を上部の余白の分だけ下げて置く。マウスオーバーで、日本語で、推定上限額が求められている枠のうち最も長い枠を31日に換算した参考値であることを示す。

枠の長さ（分）: Hubが送る `windowMinutes` を使う。無ければ `kind` の固定表（`session`=300、`daily`=1,440、`weekly`=10,080、`billing`=43,200）を使う。どちらも無ければ長さ不明とする。新しい `kind` は、この固定表に追加する。

枠ラベル: 枠の長さから決める。1日未満は `5h` の形式、1日以上は `7d` の形式、約1か月（28〜31日）は `1mo` とする。長さ不明の枠は `kind` の名前をそのまま示す。

残り時間: 現在時刻からリセット時刻までの差とし、1日未満は「Xh Ym」（1時間未満は「Ym」）、1日以上は「Xd Yh」で示す。リセット時刻が無い枠は「—」、過去の時刻は「0m」とする。

ペース: 残量（%）÷（理想の残量 × 100）とする。理想の残量は、残り時間 ÷ 枠の長さ（0〜1に収める）とする。長さ不明、リセット時刻なし、理想の残量が0のいずれかの枠は、ペースを判定しない。

円弧の色: ペースが0.8以上のとき現行の紫（正常）、0.5以上0.8未満のとき黄 `#fab219`（注意）、0.5未満のとき赤 `#f0616d`（危険）とする。判定しない枠は紫とする。

凡例: 切り替えの左に、英語で `Pace ● ≥0.8 ● ≥0.5 ● <0.5` を色付きで示す。マウスオーバーで日本語の説明（Paceは残量÷理想の残量、正常・注意・危険の各範囲）を示す。

推定上限額: 同じ枠の同じリセット周期の中で記録した2つの計測点から、「2点間の推定コストの増加 ÷ 2点間の使用率の増加 × 100」で求める。推定コストの増加は、選択したHubの全端末について、枠の提供元と同じツールの累計の推定コストの差とする。

## 受け入れ条件
- 設定した全Hubが、未受信のHubも含めて Hub別の区画から到達できる。一度に見えるのは1ページの2件までとする。
- 画面を開いた直後は期間「今日」が選択され、Hub別は先頭のページである。
- 合計・Hub別・内訳の値が、選択した期間の保存済み利用実績の合計と一致する。推定コストが無い実績は、コストの合計に含めず、トークン数だけを数える。
- 利用枠は、選択したHubが報告した枠だけを表示する。
- 推定上限額は、次の条件をすべて満たす枠だけ金額で表示し、満たさない枠は「Estimating」と表示する。
  - 同じリセット周期の計測点が2つある。
  - 2点間の使用率の増加が1ポイント以上ある。
  - 2点間の推定コストの増加が0より大きい。
- 推定上限額の値が、保存済みの2つの計測点から上の式で求めた値と一致する。
- 時刻はブラウザーのローカル時刻で表示する。
- トークン数は K・M などに略さず、桁区切りの整数で表示する。
- トークン数と推定コストは、表示する値が変わるたびに（画面を開いたとき（再読み込みを含む）、期間を切り替えたとき、表示中に同期で値が変わったとき）、変わった桁だけがスロットのリールのように1周以上回り、左の桁から順に新しい値で止まる。値が増えたときは上へ、減ったときは下へ回る。画面を開いたときと、同期で新たに表示された値（未受信だったHubの受信など）は、全桁が0から回る。桁区切り・通貨記号・小数点と「—」は回さない。
- 同期で表示中と同じ値が届いたときは回さない。
- OSの「アニメーションを減らす」設定が有効な場合は、回さずに新しい値をそのまま表示する。
- 円の重ね方（外側が短い枠、内側が長い枠、1円最大2枠、余りは同じグループの次の円）が、上の規則どおりである。
- 1契約で複数グループを報告するとき（Antigravityの Gemini と Claude/GPT の5時間・weekly）、グループごとに円が分かれ、各円に5hと7dが重なる。
- 残り時間が、現在時刻とリセット時刻の差を、上の書式で示している。画面を開いたままでも、1分ごとに残り時間とペースを再計算して表示する（取得し直しはしない）。
- 円弧の色が、ペースの閾値どおりに紫・黄・赤になる。判定しない枠は紫のままである。
- 推定上限額の求め方と表示条件は変えない。表記は「≈ 金額」または「Estimating」とする。
- 円の右上の月換算上限額が、推定上限額が求められている枠のうち最も長い枠の推定上限額と長さから、上の式で求めた値と一致する。推定上限額が求められている枠がない円と、長さ不明の円には、何も出ない。
- 画面の見出し・項目名は英語で表示する。Hub名、アカウント・プランの表示名、枠グループ名はデータの値をそのまま表示する。枠のラベルは、枠の長さから決めた表記で表示する。
- 提供元・ツール・モデルはHubが送る識別子をそのまま表示し、推定コストが無い値は「—」と表示する。
